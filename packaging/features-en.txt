NEXVARY DISK CARE 0.5.0
Storage diagnostics, metadata recovery and verified imaging

INCLUDED FEATURES
- Arabic RTL / English interface, colored icons and developer page
- Physical disk discovery and bundled SMART diagnostics
- Read-only surface scan; no claim of physical repair
- Rescue imaging with explicit resume and durable per-block JSONL checkpoints
- Resume checks source identity, destination file identity and every committed SHA-256
- Failed 1 MiB reads subdivided to 512/4096-byte sectors, with 0-5 extra retries
- NTFS deleted resident files and nonresident/sparse data with complete MFT runlists
- exFAT deleted entry sets, contiguous extents and surviving fragmented FAT chains
- FAT32 deleted files, surviving long names, live folder paths and retained FAT chains
- GPT (CRC validated), primary MBR and extended/logical MBR image partitions
- Streaming extraction without the former 64 MiB per-file memory limit
- Configurable metadata file count: default 100000, maximum 1000000
- Original names/folders where surviving metadata permits; collision-safe output
- Complete / partial / candidate classification, manifests, SHA-256 and readback
- Streaming PNG CRC checks and JPEG signature candidates
- Image inspection and SHA-256 verified copying
- USB/SD/MMC formatting, partition creation/deletion and GPT/MBR layouts
- Protected system disks and target-specific destructive-operation confirmation
- Windows x64 UEFI/GPT and BIOS+UEFI/MBR installation-media preparation
- WIM staging before disk changes and per-part SHA-256 copy verification
- Linux hybrid image writing, volume locking and SHA-256 readback
- Flash/card capacity sampling, filesystem maintenance and local JSON reports

IMPORTANT LIMITS
Complete recovery means byte coverage, not proof that deleted data survived overwrite.
Overwritten/TRIM-discarded bytes cannot be reconstructed. NTFS compressed/encrypted
streams and external MFT ATTRIBUTE_LIST extensions are reported as unsupported. Deleted FAT32
folders require retained chains and dot entries; cleared chains are refused and FAT32 results remain candidates.
Resume requires an identifiable source and the original image/map pair. Physical
rescue destination mapping is Windows-only. Surface scanning still reports 1 MiB blocks.
GPT images support 512/4096-byte partition-table sectors; MBR assumes 512. Resource limits and
unsupported/corrupt entries appear in reports. No firmware flashing or physical repair.
Copied boot files and ISO markers do not prove bootability or Secure Boot support.

Offline GRUB repair from live Linux (bundled helper, not executed on Windows): ext4, BIOS/MBR and UEFI without Secure Boot, verified backups and identity checks.
4Kn GPT images, retained deleted FAT32 folders and supported NTFS file ATTRIBUTE_LIST extents.
Windows can restore priority of an existing GRUB/shim UEFI entry, with BCD/firmware backup. Missing EFI files are not recreated.
