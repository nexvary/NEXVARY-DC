# تقرير NEXVARY Disk Care 0.7.0

نشر ملفات هذا الإصدار مشروط بنجاح اختبارات نفس Commit. ملف release-manifest.json يتضمن Commit ورقم Actions وحجم وSHA-256 لكل ملف، ونتائج النقل المباشر وإقلاع Windows المثبّت داخل الآلة الافتراضية. وجود اختبار في المصدر لا يكفي؛ راجع نتيجة التشغيل وملف البيان قبل اعتبار الإصدار مؤهّلًا.

## المنفذ

- محول Linux منفصل للقراءة المباشرة عبر AHCI وMMIO/DMA باستخدام OpenSuperClone 2.5.0 المقيد والمثبت المصدر. ليس تقييم help/version فقط؛ NEXVARY يولد أوامر IDENTIFY وREAD DMA EXT ويتلقى البيانات ويكتب الصورة وخريطة تقدمها.
- اختيار PCI والمنفذ قبل استكشاف MMIO، ورفض المتحكم الذي يحوي قرصًا ظاهرًا لنظام التشغيل، وحماية الهوية الفعلية قبل أي تعديل عند الاستئناف.
- دفعات 512 KiB تناسب جدول DMA، وذاكرة محدودة، والتحقق من حشو المسافات في هوية ATA، وقراءات قطاعية 512 بايت مع محاولات محدودة عند الخطأ.
- مرور سريع يؤجل مناطق الخطأ، وإعادة محاولة انتقائية في صورة جديدة، وقراءة القطاعات الناقصة بالعكس داخل الجزء، ومهلة ATA من 1..60 ثانية، وتصدير خريطة ddrescue متحقق منها. Virtual Disk وOSCDriver وDirect IDE وتحليل الرؤوس غير مدمجة.
- حفظ تقدم ومناطق غير مقروءة وSHA-256 لكل جزء، وإلغاء واستئناف وفحص ذيل انقطاع التشغيل، مع readback للوجهة.
- تحكم اختياري بمرحّل DCTTech USBRelay2/4/8 محدد الهوية لقناتي +5V/+12V المعزولتين للمصدر، مع ميزانية دورات وتأخير وفحص حالة ومحاولة إعادة الطاقة عند فشل إرسال USB.
- الحفاظ على وظائف الاستعادة NTFS/exFAT/FAT32 وGPT/MBR والواجهة العربية/الإنجليزية وSMART وحماية العمليات وتجهيز الإقلاع وإصلاح GRUB الموجودة.

## اختبارات الإصدار المطلوبة

- Linux: 18 اختبار CTest، و6 اختبارات أمان إصلاح الإقلاع، و19 اختبارًا للنقل/الطاقة والمراحل وخريطة التبادل.
- Windows: 21 اختبار CTest، و6 اختبارات أمان إصلاح الإقلاع، والاختبارات المشتركة الجديدة؛ فحص sysfs خاص بـLinux ولا يعمل على Windows.
- العربية والإنجليزية، الحزمة المحمولة، وتثبيت البرنامج وتشغيله وإزالته على Windows.
- قرص AHCI افتراضي عبر محرك DMA الفعلي: مقارنة الصورة بالأصل باستخدام SHA-256، الإلغاء والاستئناف، رفض تغير الهوية، وفحص أن طبقة المصدر المؤقتة لم تتلق أي كتابة بيانات. الصورة المرجعية تبقى للقراءة فقط كـbacking file.
- أخطاء قراءة وقطاع ناقص، حدود الصورة، نقص المساحة، فساد الصورة والخريطة، الهوية المتغيرة، ورفض أقراص المتحكم الظاهرة؛ حالات حتمية بمحاكاة أخطاء النقل.
- بروتوكول المرحّل وحالات انقطاع الاتصال واستعادة القناتين وحدود المحاولات؛ محاكاة USB وليست اختبار الكهرباء الفعلية.
- إقلاع Linux المرجعي وإصلاح GRUB ثم الوصول إلى النواة عبر BIOS وUEFI دون Secure Boot.
- Windows 11 Enterprise LTSC Evaluation مثبّت فعليًا من WIM إلى قرص افتراضي داخل Windows PE، ثم إقلاع وتسجيل دخول داخل QEMU/KVM عبر BIOS وUEFI وUEFI Secure Boot. فحص الحالة يأتي من سجل Windows داخل الضيف، وليس من اسم ملف OVMF أو نجاح نسخ EFI.

## القيود والأعمال غير المكتملة

- إصلاح Firmware وService Area وTranslator **لم يُنفَّذ لأي عائلة، ولا توجد عائلة معتمدة**؛ عدد العائلات المعتمدة صفر. لا توجد في الطلب موديلات وإصدارات وإجراءات موثقة تسمح بتنفيذ إصلاح محدد والتحقق منه. لا يُمكَّن سكربت إصلاح عام.
- المحول المباشر أداة Linux للمختصين، لا محرك AHCI أو مشغّل نواة داخل Windows. يتطلب مصدرًا يمكن تحديده عبر IDENTIFY وقطاعات 512 بايت وBAR5 تحت 4 GiB وبيئة نواة تسمح بالوصول؛ لا يدعم IOMMU النشط أو المتحكم المشترك.
- تأهيل الإصدار يتطلب أيضًا تشغيل كود تجهيز Windows الإنتاجي داخل الضيف على USB افتراضي، ثم إقلاع هذا USB حتى Windows PE في الأنماط الثلاثة. يُفحص رفض قرص النظام وتغيّر هوية الوجهة ونقص المساحة قبل المسح. يضيف الاختبار سكربت shell إلى WIM لإخراج سجل نصي من داخل الضيف بعد الإقلاع على FAT تجريبي منفصل؛ ملفات EFI الموقعة لا تتغير. لا يُعد مجرد وجود الاختبار دليل نجاح: يجب نجاح تشغيل Actions ووجود النتائج في البيان.
- نجاح صورة Windows المحددة مع مفاتيح OVMF لا يعني توافق أي ISO أو أي Firmware أو Secure Boot عمومًا. إصلاح GRUB الحالي يرفض Secure Boot المفعّل.
- الكهرباء الفعلية وتوقيت SATA وأداء المصدر المتعطل يحتاج اختبار أجهزة. البرنامج لا يتحقق من التوصيل الكهربائي بدل المختص، ولا يستعيد بيانات مطموسة أو أزالها TRIM، ولا يجدد طبقات القرص المغناطيسية.

التجارب الفعلية وخطواتها في HARDWARE-TESTS-AR.md؛ تشغيل المحول وإعداداته في DIRECT-AHCI-AR.md. تبقى بيانات الموديل والإصدار والإجراء الموثق شرطًا لبدء اعتماد إصلاح Firmware، وليست طلب إذن للاستمرار في تطوير بقية البرنامج.
