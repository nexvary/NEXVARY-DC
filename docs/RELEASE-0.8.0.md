# NEXVARY Disk Care 0.8.0

Retains the tested filesystem recovery, protected storage/media preparation, GRUB repair and restricted Linux OpenSuperClone direct-AHCI features from 0.7.0. Adds full native ATA/NVMe SMART tables, local sampled trends, bounded refresh/alert preferences, raw hex/decimal and temperature-unit display, serial masking, and monitoring that stops on read failure or changed serial. Nonzero ATA 05/C5/C6 produces caution even if the overall SMART flag passes. Raising notification limits does not hide underlying risk.

Windows additionally bundles the complete unmodified pinned CrystalDiskInfo 9.9.2 Standard Edition package and corresponding source/notices. Its reports can be imported into NEXVARY; its explicitly identified original advanced panel provides the upstream AAM/APM, graphs, alarms, mail, resident monitoring, themes/languages and controller settings. Those controls are not all reimplemented in Qt. Automatic saved AAM/APM application is disabled at launch. No physical controller/bridge support, SMTP delivery or disk-control actuation is inferred from software startup testing. Core MIT and accompanying dependency licenses, including AMD_RC2t7 terms, are retained.

The 0xc0000001 workspace provides data-first guidance linked to actual existing image rescue and recovery-media preparation. It does not automatically rebuild BCD or run SFC/DISM, does not identify the error's cause from the code alone, and does not repair physical disk damage. Firmware/SA/Translator certified families remain zero. OSCDriver virtual disk, Direct IDE and head analysis remain unintegrated.

Release publication requires native Linux/Windows tests, Arabic/English UI proof, bundled-engine parsing and visible advanced-panel startup/normal close, portable/install/uninstall checks, direct-AHCI DMA/targeted retry VM tests and installed Windows plus production-prepared virtual USB boot in BIOS/UEFI/UEFI Secure Boot, all on the delivered commit. Read release-manifest.json and Actions results before claiming those gates passed.

Recovery now validates an adjacent native or direct-AHCI rescue map against the complete committed image prefix before creating output. Known missing/deferred source bytes produce partial files with sourceMissingBytes and map provenance; later readable fragments are retained. Missing metadata is refused rather than used as allocation evidence. Torn/uncommitted tails remain unknown; corrupt/ambiguous maps are rejected. Images without maps retain the explicit original-content integrity limitations.
