# تقرير تسليم NEXVARY Disk Care 0.8.0

تأهيل الإصدار مرتبط بالـCommit ورقم Actions داخل `release-manifest.json` المنشور مع الحزم. نجاح البناء أو وجود اختبار في المستودع لا يثبت نجاح الإقلاع؛ النشر الآلي لا يحدث إلا بعد نجاح الاختبارات المطلوبة على نفس Commit. يحتوي البيان على الحجم بالبايت وSHA-256 لكل ملف.

## المنفذ

- استعادة NTFS/exFAT/FAT32 من بيانات التخصيص الباقية، ملفات مقيمة ومجزأة، أسماء ومجلدات حين تسمح الأدلة، GPT بقطاعات 512/4096 وMBR الممتد. استخراج متدفق يتجاوز حد 64 MiB السابق، وتصنيف كامل/ناقص/مرشح مع بصمة وreadback.
- إنقاذ قابل للإلغاء والاستئناف مع هوية المصدر والوجهة وخريطة SHA-256 وحبيبات قطاعية ومحاولات محدودة. إعادة محاولة انتقائية تحفظ الصورة الأولى وتقرأ المناطق الناقصة فقط إلى صورة جديدة.
- تكامل OpenSuperClone 2.5.0 GPL منفصل ومقيد لـLinux: AHCI MMIO/DMA فعلي، رفض المتحكم المشترك، IDENTIFY وREAD DMA EXT فقط، مرور سريع وتأجيل مناطق الخطأ، قراءة عكسية داخل المناطق الناقصة، مهلة ATA وتصدير ddrescue، ومرحّل طاقة محدد للمصدر. Windows يضم المصادر والتعليمات، ولا يتضمن مشغّل AHCI مباشرًا.
- ربط محركات الاستعادة بالخريطة المجاورة بعد التحقق من SHA-256. المناطق المفقودة/المؤجلة تجعل الملف ناقصًا مع عدد البايتات المفقودة؛ المقاطع المقروءة اللاحقة تبقى محفوظة. بيانات التخصيص المفقودة والخرائط التالفة/المتعارضة تُرفض.
- جدول SMART كامل لـATA/NVMe ومراقبة واتجاهات محلية أثناء فتح التطبيق. 05/C5/C6 غير الصفرية تبقى تحذيرًا رغم رفع حدود الإشعار. الخطأ وتغيّر الرقم التسلسلي يوقفان المراقبة.
- CrystalDiskInfo 9.9.2 كاملًا دون تعديل على Windows، مع مصدره وتراخيصه وبصماته، استيراد التقرير ونافذته الأصلية للوظائف المتقدمة. لا تُنسب تبعية AMD المغلقة إلى MIT، ولا يُدعى إعادة كتابة كل وظائفه في Qt. التعطيل التلقائي لإعدادات AAM/APM المحفوظة عند التشغيل.
- حماية أقراص النظام والهوية ونقص مساحة الوجهة، تجهيز Windows BIOS/UEFI والكتابة الهجينة Linux مع readback، إصلاح GRUB المحدود واستعادة أولوية إدخاله الموجود، وشاشة تشخيص 0xc0000001 مرتبطة بالإنقاذ والوسائط. الشاشة الأخيرة إرشاد وليست إعادة بناء BCD تلقائية.

## الاختبارات المطلوبة للتسليم

23 هدف CTest على Linux و26 على Windows، و19 اختبار النقل/المراحل/الطاقة والخريطة على Linux و17 مشتركة على Windows، و6 حالات أمان إصلاح الإقلاع. تتضمن صور ملفات محذوفة ومجزأة ومقارنة المحتوى وSHA-256، ملف NTFS بحجم 65 MiB، فساد metadata وحدود الصورة، نقص المساحة، الإلغاء والاستئناف وتغير الهوية، والواجهة العربية/الإنجليزية.

Windows: الحزمة المحمولة وتشغيلها دون Qt خارجي، التثبيت والتشغيل والإزالة، المحرك الأصلي المرخص والتحقق من نافذته وإغلاقه واستيراد التقرير. قرص CI افتراضي قد لا يقدم SMART؛ ذلك يسجل غير معروف ولا يؤهل دعم محول حقيقي.

VM: AHCI يقرأ عبر المحرك الفعلي ويطابق SHA-256، إلغاء واستئناف ورفض الهوية وإعادة محاولة قطاع محدد دون تعديل الصورة الأولى أو كتابة بيانات المصدر. Linux المرجعي وإصلاح GRUB يصلان إلى النواة في BIOS/UEFI دون Secure Boot. Windows LTSC Evaluation محدد البصمة يُثبت ويقلع حتى تسجيل الدخول، ثم كود الإنتاج يجهز USB افتراضيًا ويقلع منه Windows PE عبر BIOS وUEFI وUEFI Secure Boot؛ يحمي قرص النظام ويرفض الهوية المتغيرة ونقص المساحة قبل التعديل. ملفات EFI الموقعة لا تتغير، ويضاف hook نصي داخل WIM للإثبات فقط. لا تُوزع صور Microsoft.

## القيود المتبقية

- عائلات إصلاح Firmware/Service Area/Translator المعتمدة: **صفر**. لا يوجد مسار إصلاح عام ولا تحديث Firmware عشوائي. لا يجدد البرنامج الطبقات المغناطيسية ولا يعكس overwrite/TRIM.
- OSCDriver virtual disk وDirect IDE وتحليل الرؤوس غير مدمجة. النقل المباشر يتطلب هوية ATA متاحة وقطاعات 512 بايت ومتحكمًا معزولًا وBAR5 تحت 4 GiB ودون IOMMU نشط؛ التفاصيل في DIRECT-AHCI-AR.md.
- NTFS المضغوط/المشفر والتدفقات المسماة وامتدادات MFT الخارجية غير مدعومة؛ ملفات ATTRIBUTE_LIST المدعومة لها اختبارات مراجع وتسلسل. سلاسل FAT الممسوحة لا تُخمن، وتبقى نتائج FAT32 مرشحة للفحص.
- «كامل» يعني تغطية البايتات وفق metadata وليس إثبات أن المحتوى الأصلي لم يُكتب فوقه. SHA-256 للنسخ لا يثبت صحة الأصل.
- نجاح ISO واحد مع مفاتيح OVMF لا يعتمد كل الأجهزة أو صور Windows أو قواعد Secure Boot. GRUB الحالي يرفض Secure Boot.
- لم يُختبر تشغيل أوامر SMART/AAM/APM على أجهزة فعلية، أو الكهرباء الفعلية لمرحّل الطاقة، أو إرسال بريد SMTP. إعداد البريد وظيفة اللوحة الأصلية تتطلب إعداد المستخدم؛ لا تُرسل رسائل في التأهيل.
