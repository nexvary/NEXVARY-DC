# الإنقاذ المباشر AHCI — 0.7.0

هذه أداة Linux للمختصين، وليست مسار AHCI داخل نسخة Windows. تشغّل نسخة مقيدة من OpenSuperClone 2.5.0 كعملية منفصلة. تعديل المصدر يقصر الاستكشاف على متحكم PCI ومنفذ محددين قبل الوصول إلى MMIO، ويمنع اختيار قرص ظاهر لنظام التشغيل. أوامر المصدر التي يولدها NEXVARY هي IDENTIFY وREAD DMA EXT فقط، ولا توجد كتابة Firmware أو Service Area أو Translator.

## المتطلبات والحدود

- Linux حي يعمل من RAM أو من متحكم آخر. متحكم SATA مستقل في وضع AHCI، مجال PCI رقم 0000، وBAR5 تحت 4 GiB؛ القطاعات المنطقية 512 بايت فقط.
- إخفاء منافذ المصدر عند إقلاع Linux وفق إرشادات OpenSuperClone. لا تفصل متحكم النظام بواسطة unbind. ترفض الأداة **المتحكم كله** إذا ظهر أي قرص تابع له في `/sys/class/block`؛ وهذا يشمل المصدر والوجهة وأقراص النظام.
- لا يدعم المحول IOMMU النشط أو مجموعة IOMMU مشتركة. لا تغيّر إعدادات الجهاز العامل لإجبار الأداة؛ استخدم بيئة إنقاذ مستقلة. المصدر المجهول الهوية أو الذي لا يستطيع IDENTIFY غير مدعوم.
- يتطلب root و`/dev/mem` وإظهار PFN في pagemap. قد تمنع سياسات النواة الوصول؛ لا تتجاوز الحماية تلقائيًا.
- عملية محرك منفصلة لكل قراءة، بحد أقصى 1 MiB، لذا الأداء يحتاج قياسًا على الأجهزة. لا يُقتل محرك DMA عند الإلغاء؛ يُحفظ التقدم عند حد القراءة المكتملة التالية.
- خريطة JSONL بجانب الصورة تسجل SHA-256 لكل جزء ومناطق الخطأ. الاستئناف يفحص الهوية وموقع الوجهة وinode والخريطة وجميع الأجزاء المكتوبة، ثم يزيل ذيل الكتابة غير المثبت فقط. لا يحمّل الصورة أو الخريطة كاملة في الذاكرة.
- أخطاء القراءة الكبيرة تُفحص مجددًا بقطاعات 512 بايت، مع 0..5 محاولات إضافية. تُسجل القطاعات غير المقروءة ويُكتب صفر كعنصر نائب؛ اكتمال القراءة لا يثبت سلامة ملفات المصدر.

## البناء والتشغيل

```sh
sudo apt-get install cmake pkg-config libgtk-3-dev libusb-dev libconfig-dev gettext xxd
python3 scripts/qualify_opensuperclone.py --direct --output out/osc-direct
sudo python3 scripts/direct_rescue.py --engine out/osc-direct/build/src/opensuperclone/opensuperclone --qualification out/osc-direct/qualification.json --identity source.json --output /media/other-controller/rescue.img --retries 1
```

`source.json` يحدد هوية القرص كما هي في ATA IDENTIFY، بدون فراغات الحشو:

```json
{"pci":"0000:03:00.0","port":0,"serial":"EXACT_SERIAL","model":"EXACT MODEL","firmware":"EXACTREV","bytes":1000204886016}
```

للاستئناف، أعد الأمر نفسه وأضف `--resume`. لا تستعمل هوية تخمينية أو أسماء موديلات عامة. رقم المنفذ صفري داخل AHCI وليس رقم القرص في Windows.

## التحكم بالطاقة

اختياري عبر `--relay relay.json`، ويتطلب `python3-usb` وlibusb. التنفيذ يقبل DCTTech USBRelay2/4/8 فقط، VID:PID `16c0:05df`، وبهوية داخلية فريدة من خمسة أحرف. لا يقبل معرفًا مكررًا، ولا يتحكم بكل القنوات دفعة واحدة.

```json
{"id":"ABCDE","rails":{"5v":1,"12v":2},"sourceOnlyWiringConfirmed":true,"maxCycles":1,"offSeconds":2,"settleSeconds":5}
```

يجب أن يتحقق المختص فعليًا أن القناتين تعزلان **+5V و+12V للمصدر وحده** عبر نقاط NO، وأن المصدر يعمل عندما تكون القناتان ON، والوجهة والحاسوب لا يتأثران. البرنامج لا يستطيع إثبات التوصيل الكهربائي. لا يوجد تشغيل أولي للطاقة أو دعم قرص 3.3V أو مرحل غير معروف. إعداد `sourceOnlyWiringConfirmed` شهادة من المشغّل، وليس اكتشافًا آليًا.

تتم دورة الطاقة بعد خطأ قراءة قبل محاولة إضافية فقط، بحد عالمي 1..3 دورات. تُفحص هوية المرحل وحالته قبل كل إرسال وبعده، وتُحاول إعادة القناتين إلى ON حتى عند فشل إحدى عمليات USB. فشل الاستعادة يوقف الإنقاذ، وتغير ATA IDENTIFY بعد العودة يوقف القراءة. لا تُفسَّر إعادة تشغيل القرص باعتبارها إصلاحًا لتلف مادي.

## الاختبارات

اختبارات تلقائية تقارن المحتوى وSHA-256 وتغطي الإلغاء والاستئناف وذيل انقطاع الكتابة والخريطة التالفة وتغيّر الهوية ونقص المساحة وحماية المتحكم والمحاولات القطاعية. مرحل الطاقة يُختبر ببروتوكول USB محاكى مع أخطاء الاتصال واستعادة القناتين؛ الكهرباء الفعلية غير مختبرة. اختبار QEMU مستقل يقرأ قرص AHCI افتراضيًا عبر MMIO/DMA ثم يستأنف الصورة ويقارن SHA-256، مع مصدر host للقراءة فقط. يجب مراجعة نتيجة Actions للإصدار؛ وجود كود الاختبار وحده ليس نجاحًا له.

## Firmware / Service Area / Translator

عدد عائلات الأقراص المعتمدة للإصلاح بهذه النسخة: **صفر**. لا يغيّر هذا المحول Firmware أو SA أو Translator. للحصول على اعتماد يلزم موديل كامل وإصدار Firmware ومعرف العائلة وإجراء موثق وتوافق الوحدات/ROM ونسخ احتياطية قابلة للتحقق واسترجاع عند الفشل واختبار جهاز تلك العائلة. سكربت WD ROYL عام أو نجاح قراءة AHCI لا يحقق هذه الشروط. لا توجد حاليًا هذه المعلومات في الطلب أو المستودع؛ لذلك لا يمكن تسليم إصلاح معتمد لهذه العائلات دون تحديدها.
